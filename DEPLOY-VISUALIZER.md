# DEPLOY — Yard Design Preview (AI Visualizer)

The `/visualizer/` page lets a visitor upload a photo of their yard, pick features
(pavers, fire feature, pergola, turf…), leave their contact info, and receive a
photorealistic redesign of *their actual yard* — generated by Google Nano Banana Pro
via the Magnific (Freepik) API. The design shows on screen and is emailed to them;
you get a lead notification with their selections and timeline.

## How it works (30 seconds)

1. Visitor uploads photo → picks up to 4 features + a style → enters name/email/ZIP/timeline.
2. The Worker (`worker/index.ts` routing to `worker/visualize.ts`) verifies Turnstile,
   rate-limits (3 designs/day per email, 8 per IP), stores the photo in R2, starts a
   Nano Banana Pro task at Magnific, and **immediately emails you the lead**.
3. The page polls `worker/visualize-status.ts` (~45–60 s). On completion the image is
   copied to R2, shown on screen with hold-to-compare and a ballpark range (same
   numbers as `/estimator/`), and emailed to the visitor with a Book-a-Consultation CTA.
4. Every image is labeled "Concept visualization" (brand rule), and downloads are watermarked.

Without `MAGNIFIC_API_KEY` the backend runs in **mock mode** (echoes the uploaded
photo back after ~8 s) — that's what you see on localhost.

## Architecture note (July 2026)

This site deploys as a Cloudflare **Worker with static assets** (auto-migrated from
Pages; builds run `npm run build` then `npx wrangler deploy` from `main`).
`wrangler.jsonc` is the source of truth for bindings:

- `VISUALIZER_KV` → KV namespace `sdlr-visualizer` (id `9ca3292…`) — created 2026-07-13 ✅
- `VISUALIZER_BUCKET` → R2 bucket `sdlr-visualizer` — ⚠️ requires the (free-tier) R2
  subscription to be enabled on the account, then the bucket created. **A deploy will
  fail until this bucket exists.**
- Vars `FROM_EMAIL`, `LEAD_NOTIFY_EMAIL` — set in `wrangler.jsonc`, edit there.

The unmerged `cloudflare/workers-autoconfig` branch (created by Cloudflare's bot) is
superseded by this setup and can be deleted.

## Remaining setup checklist

| Step | Where | Status |
| --- | --- | --- |
| KV namespace `sdlr-visualizer` | dash → Storage → Workers KV | ✅ done 2026-07-13 |
| Turnstile widget (`sdlr-visualizer`, Managed, both hostnames) | dash → Turnstile | ✅ done 2026-07-13 |

| Enable R2 subscription ($0 now, 10 GB/mo free) | dash → R2 | ⬜ needs Gio's OK |
| Create R2 bucket `sdlr-visualizer` | dash → R2 → Create bucket | ⬜ after subscription |
| Secret `MAGNIFIC_API_KEY` | Worker → Settings → Variables and secrets (type **Secret**) | ⬜ Gio pastes (magnific.com → API keys; **API credits are separate from the unlimited web/MCP plan**) |
| Secret `TURNSTILE_SECRET_KEY` | same screen | ⬜ Gio pastes (dash → Turnstile → sdlr-visualizer widget → Secret key) |
| Secret `RESEND_API_KEY` | same screen | ⬜ Gio signs up at resend.com (free 3k emails/mo), verifies the domain, pastes key |
| Optional `LEAD_WEBHOOK_URL` (GoHighLevel inbound webhook) | same screen | ⬜ optional |
| Push `main` | git | ⬜ after R2 bucket exists |

Missing email keys don't break anything — emails are skipped silently until configured.

## Costs & guardrails

- Nano Banana Pro via API ≈ a few cents per 2K image. Worst case capped by rate
  limits (3/day/email, 8/day/IP) + Turnstile bot blocking.
- R2 storage at this volume is pennies; KV task records expire after 7 days.
- If the Magnific API errors, the visitor sees a friendly retry message — the lead
  was already captured and emailed at submit time.
